# 大学生健康作息管理系统（SleepManagement）

**Stack Overflow 小组**：王晨瑜、董弈齐、曾梓航

本项目是一款面向大学生群体的桌面端健康作息管理工具。它以“睡眠打卡—本地存档—数据分析—可视化反馈—健康提醒”为主线，帮助用户记录每天的入睡、起床、午睡、运动、久坐等信息，并通过睡眠评分、趣味称号、成就系统、周报分析和图表展示，让原本抽象的作息习惯变得可观察、可回顾、可调整。

项目使用 **Qt 6 + C++17 + CMake** 开发，支持 Windows 与 macOS 平台构建，并额外实现了系统托盘、桌面悬浮球、键盘活跃度监测、DeepSeek API 周报分析与 PDF 导出等功能。

---

## 一、项目定位

大学生群体常见的问题包括：

- 入睡时间不稳定，容易在凌晨后才睡；
- 早八、考试周、项目周导致睡眠时长波动明显；
- 久坐、缺少运动、白天补觉等行为与夜间睡眠相互影响；
- 手动记录作息容易忘记，长期趋势难以直观看出。

因此，我们将系统设计为一个轻量但完整的“作息守护工具”：既能快速记录，也能在后台提醒；既有本地算法分析，也能接入大模型生成更有趣的周报；既能用日历回顾单日数据，也能用图表查看近七天趋势。

## 二、核心功能

### 1. 每日作息记录与本地持久化

系统支持记录以下每日数据：

- 入睡时间；
- 起床时间；
- 午睡时长；
- 运动时长；
- 久坐时长；
- 睡眠日记；
- 是否通宵；
- 睡眠评分、是否熬夜、是否睡懒觉等分析结果。

所有数据会以 `yyyy-MM-dd.json` 的形式保存在系统应用数据目录中。程序启动时会自动读取历史数据，用户点击日历日期后也会自动回填对应日期的记录。

### 2. “作息日”逻辑与跨天睡眠处理

大学生的睡眠经常横跨自然日期，例如 5 月 28 日晚上入睡，5 月 29 日早上起床。为避免数据错位，项目没有简单按照自然日切分，而是使用“作息日”逻辑：

- 某一天白天的午睡、运动、久坐数据；
- 当天晚上开始的夜间睡眠；
- 次日早上结束的起床时间；

会共同保存到同一个作息日文件中。

例如 `2026-05-28.json` 表示：

- 5 月 28 日白天的午睡、运动、久坐；
- 5 月 28 日晚上的入睡时间；
- 5 月 29 日早上的起床时间。

对于凌晨后才入睡的情况，程序会结合用户自定义的熬夜区间，自动判断该睡眠应归属到哪个作息日。

### 3. 一键打卡、手动补录与通宵标记

主界面提供两个核心按钮：

- **准备入睡**：记录当前系统时间为入睡时间，并保存临时 JSON 数据；
- **我醒了**：记录当前系统时间为起床时间，并触发当日结算。

此外，系统还支持：

- 手动修改入睡时间；
- 手动修改起床时间；
- 手动补录过去日期的数据；
- 点击“我熬穿了”标记通宵未睡；
- 重新点击入睡按钮覆盖误点数据；
- 保存并生成当日简报。

这一设计兼顾了实时打卡和事后补录，减少了用户因为忘记点击按钮而导致整天数据丢失的情况。

### 4. 睡眠评分与趣味称号

系统会基于夜间睡眠时长、是否通宵、是否睡懒觉等指标计算睡眠评分。大致规则如下：

- 通宵：严重扣分；
- 少于 6 小时：低分；
- 6—7 小时：中等；
- 7—9 小时：较优；
- 9—10 小时：略低；
- 超过 10 小时或明显睡懒觉：降低评分。

每日结算后，程序会生成带有趣味表达的“清晨日结报告”，例如熬夜、睡懒觉、理想睡眠等不同状态会对应不同称号，使反馈更有参与感。

### 5. 日历回顾与颜色标记

左侧日历用于查看历史记录。用户点击任意已记录日期后，右侧会自动显示该日入睡、起床、睡眠时长、午睡、运动、久坐与日记内容。

日历会根据睡眠状态自动染色：

| 颜色 | 含义 |
|---|---|
| 红色 | 通宵未睡 |
| 紫色 | 睡懒觉或起床明显晚于一般起床时间 |
| 黄色 | 睡眠评分较低 |
| 蓝色 | 睡眠评分中等 |
| 绿色 | 睡眠评分较好 |

主界面还提供图例说明，方便用户一眼观察一段时间内的作息状态。

### 6. 近七天周报分析：本地算法 + 大模型 API

系统支持生成近七天周报，读取范围为“当前选中日期向前最多七天”。

周报有两种模式：

1. **本地算法模式**  
   如果用户没有填写 API Key，程序会调用本地 C++ 算法生成周报，统计近七天的熬夜天数、补觉情况、平均睡眠时长和综合睡眠分，并给出本地评价。

2. **AI 分析模式**  
   如果用户填写了 DeepSeek API Key，程序会把近七天 JSON 数据打包发送给大模型，请模型以“修仙宗门掌律大长老”的风格生成 Markdown 周报，包括掌律周评、风险评估和下周建议。

当 API Key 格式错误或未填写时，系统会自动降级为本地周报，保证核心功能不依赖网络。

### 7. PDF 导出

生成周报后，用户可以点击“导出 PDF”，将 AI 或本地分析区域中的内容导出为 PDF 文件，便于提交、留档或分享。

### 8. 睡眠图表可视化

系统提供近七天睡眠可视化图表，包括：

- **睡眠时长柱状图**：展示每日夜间睡眠与午睡叠加时长，并绘制推荐睡眠参考线；
- **睡眠评分折线图**：展示近七天睡眠评分变化趋势。

图表使用 Qt 的 `QPainter` 自定义绘制，没有依赖外部图表库，便于控制样式和细节。

### 9. 键盘活跃度与注意力曲线

项目实现了后台键盘敲击频率监测，用于粗略反映用户在电脑前的活跃程度。系统只统计按键次数，不记录具体按键内容。

功能特点：

- 每 200 ms 轮询系统级按键累计值；
- 以“每分钟敲击次数”为单位存入环形缓冲区；
- 最多保留近 8 小时数据；
- 打开“注意力曲线”窗口后可查看柱状图；
- 支持 Windows 与 macOS 的不同底层实现。

Windows 端使用低级键盘钩子统计全局按键次数；macOS 端使用 CoreGraphics 事件计数器。上层统一由 `KeyMonitor` 处理数据，体现了跨平台抽象设计。

### 10. 系统托盘、桌面气泡与后台守护

程序关闭主窗口时不会直接退出，而是最小化到系统托盘继续运行。托盘菜单支持：

- 显示主窗口；
- 退出程序。

在设定的熬夜区间内，如果系统检测到用户长时间没有记录入睡，会通过桌面气泡发出提醒。入睡、起床、成就解锁等行为也会触发相应通知。

### 11. 桌面悬浮球快捷打卡

除主窗口按钮外，系统还提供桌面悬浮球。悬浮球始终置顶，支持拖拽移动，点击后展开两个快捷按钮：

- 我入睡了；
- 我起床了。

悬浮球与主窗口通过 Qt 信号槽连接，适合用户在不打开主界面的情况下快速打卡。

### 12. 成就系统

系统会根据历史 JSON 数据计算连续行为，并显示当前解锁的徽章。包括：

- 连续打卡 7 天、30 天；
- 连续早睡 3 天、7 天；
- 连续 3 天或 7 天睡眠评分为 3；
- 连续 3 天或 7 天睡眠评分不低于 2。

成就逻辑由独立的 `AchievementManager` 负责，不依赖 UI，主窗口只负责调用和展示结果。

### 13. 用户自定义设置

用户可以在设置窗口中调整：

- 一般入睡时间；
- 一般起床时间；
- 熬夜判定起始时间；
- 熬夜判定结束时间。

设置以 JSON 格式保存，并会即时应用到睡眠评分和熬夜判断逻辑中。时间选择支持半小时粒度，并包含防呆设计，防止设置出不合理的作息区间。

### 14. 睡眠日记

主界面动态创建了“睡眠日记”文本框，用户可以记录当晚梦境、情绪或身体感受。保存作息数据时，日记内容会随同其他数据写入当日 JSON 文件，并在点击历史日期时自动回填。

### 15. 数据清理工具

系统提供三种数据清理方式：

- 清空当前选中日期；
- 清空指定日期区间；
- 清空全部作息数据。

清理后日历颜色、成就显示和界面内容会自动刷新。

### 16. 欢迎说明书与帮助入口

程序启动时会弹出用户说明书，介绍安装运行、打卡流程、周报、图表、键盘监测、托盘、设置、数据管理与常见问题。用户可勾选“不再显示”，也可以通过主界面的“？”按钮重新打开说明书。

说明书内容被打包进 Qt 资源文件中，避免运行时因为外部文件丢失导致帮助页面无法加载。

## 五、安装与运行

### 1. 开发环境

推荐环境：

- Qt 6.5 或以上；
- CMake 3.19 或以上；
- 支持 C++17 的编译器；
- Windows 或 macOS。

### 2. 使用 Qt Creator 构建

1. 使用 Qt Creator 打开 `SleepManagement/CMakeLists.txt`；
2. 选择合适的 Qt Kit；
3. 运行 CMake Configure；
4. 编译并运行项目。

### 3. 命令行构建

在项目根目录或合适路径下执行：

```bash
cmake -S SleepManagement -B build
cmake --build build --config Release
```

### 4. macOS 注意事项

如果键盘活跃度监测没有数据，请检查系统设置中的“隐私与安全性”相关权限，必要时为程序授予输入监控权限。

### 5. Windows 注意事项

Windows 端键盘监测使用低级键盘钩子，部分安全软件可能会拦截。如果注意力曲线无数据，可以优先检查安全软件或系统权限。

## 六、基本使用流程

1. 打开程序，阅读欢迎说明书。
2. 晚上准备睡觉时点击“准备入睡”。
3. 第二天醒来后点击“我醒了”。
4. 在确认框中核对入睡和起床时间。
5. 填写午睡、运动、久坐和睡眠日记。
6. 保存后查看当日日结报告。
7. 点击日历回顾历史数据。
8. 点击“生成周报”查看近七天分析。
9. 点击“图表”查看睡眠趋势。
10. 点击“注意力曲线”查看键盘活跃度。
11. 需要时使用数据清理工具管理本地记录。

## 八、项目特色

1. **面向真实大学生作息场景**  
   系统不是只记录自然日，而是设计了更贴合作息习惯的“作息日”逻辑。

2. **本地算法和 AI 分析并存**  
   没有 API Key 时依然可以使用完整本地周报；有 API Key 时可以获得更有趣的大模型分析。

3. **功能闭环完整**  
   从记录、保存、回填、评分、日历染色、周报、图表、导出到数据清理，形成了完整使用流程。

4. **Qt 图形界面交互丰富**  
   包含日历、按钮、弹窗、托盘、悬浮球、自定义对话框、图表窗口和帮助说明书。

5. **跨平台适配设计**  
   使用条件编译区分 Windows 与 macOS 的键盘监测底层实现，同时保持上层接口统一。

6. **隐私友好的键盘监测**  
   只统计按键次数，不记录具体按键内容。

## 九、已知限制与后续可改进方向

- 自动化测试仍然不足，尤其是跨天睡眠、通宵、极端作息数据等边界情况；
- AI 周报当前依赖用户手动输入 API Key，后续可以优化 Key 管理和错误提示；
- 键盘活跃度只能粗略反映专注状态，不能完全代表真实学习效率；
- 暂未实现多设备同步和云端备份；
- 可以进一步增强 Agent 辅助开发流程，例如自动生成测试用例、重构建议和界面原型。
